六、真实网页操作脚本

1. 服务启动

启动后端 python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 和前端 npm run dev -- --host 127.0.0.1 --port 5173，确认 /api/health 返回 status=ok。

2. 登录页

打开 http://127.0.0.1:5173/login，确认页面渲染；切换注册模式，输入 username、email、password，完成注册并进入工作台。

3. Auth 新页面

从登录页进入 /forgot-password，输入邮箱提交；在未配置 SMTP 的默认环境下应显示邮件服务不可用的错误。打开 /reset-password?token=bad 应显示无效 token 相关错误。

4. Agent 草稿页

访问 /platforms/xhs/agent-drafts，确认侧边栏存在 Agent 草稿入口。先空表单提交，验证必填提示；再填写内容需求、草稿数量和图片数量提交。

5. 结果判断

默认无模型配置时，页面应显示生成失败或缺少默认模型的错误态；配置模型后，期望看到每条草稿卡片、状态、标签、图片预览，并能在草稿工坊中找到已保存草稿。

七、已知缺口与修复顺序

  • 必须先修 更新所有认证相关测试夹具：注册请求补齐唯一邮箱，直接创建 User 的地方补齐 email。
  • 建议补强 为 /forgot-password 和 /reset-password 增加后端测试，覆盖 SMTP 未配置、邮箱不存在、token 无效、token 成功重置。
  • 建议补强 前端当前只有 build，没有 Vitest 或 Playwright 固化用例；建议增加本地 E2E 冒烟，至少覆盖登录、Agent 草稿页、草稿工坊。
  • 浏览器观察 Agent 草稿页先空提交再填写内容后，旧的“请描述内容需求”校验提示仍残留在 textarea 下方，但请求已继续发出并显示后端 400 错误态；建议清理该表单校验状态。
  • 环境限制 本轮浏览器插件的 Node REPL 控制面未暴露，真实网页操作已使用本地服务加 Playwright 级浏览器脚本替代。

八、通过标准

完成标准不是“页面能打开”，而是：后端 pytest 全绿、前端 build 通过、本地服务健康、真实浏览器完成注册登录和目标页面操作、Agent 草稿在无模型配置时有清晰错误态，在模型配置可用时能创建草稿并在草稿工坊可见。
